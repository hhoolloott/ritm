# Ритм

Минималистичный личный дневник тренировок для телефона и ноутбука. React + Vite, вход и синхронизация через Supabase. Работает независимо от Sites.

## Что есть

- Заготовки «Руки», «Грудь», «Спина», «Ноги» и свободная тренировка.
- Последние кг и повторения подставляются по точному названию упражнения.
- Одно раскрытое упражнение; отметка подхода одной кнопкой.
- История, простой календарь, посещения и подходы по датам.
- Экспорт и импорт JSON. Повторный импорт не затирает уже существующие записи с теми же ID.
- Локальный черновик при ошибке сохранения и защита от одновременных изменений с разных устройств.

## Приватность

Личные заметки, история тренировок и пароли не включены в исходники и сборку. Каждая запись в Supabase привязана к вошедшему пользователю; SQL включает Row Level Security. Результаты тренировок импортируются отдельно после входа. Страница входа и сам код сайта могут быть доступны посетителям в зависимости от выбранного хостинга; приватность записей обеспечивается авторизацией и RLS в базе.

В клиентскую сборку передаётся только **publishable** или устаревший **anon** ключ Supabase. Не использовать `service_role`, secret key, пароль базы или персональные токены GitHub в `VITE_*` переменных.

## Локальный запуск

Node 22.13+.

1. `npm ci`
2. Скопировать `.env.example` в `.env.local` и заполнить URL проекта и его publishable key.
3. Выполнить `supabase/schema.sql` в SQL Editor своего проекта Supabase.
4. В Supabase Authentication → Users создать собственную учётную запись для дневника. Отключить новые регистрации, если дневником будет пользоваться только владелец. Пароль вводится непосредственно в Supabase, затем в форму входа приложения.
5. `npm run dev`

Без URL и ключа приложение показывает экран настройки и не создаёт локальную иллюзию облачного сохранения.

## Публикация из GitHub

Рекомендуется сначала создать приватный репозиторий и загрузить исходники. Поддерживается статический хостинг: команда сборки `npm run build`, выходная папка `dist`.

На хостинге указать `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. После публикации войти в дневник с одинаковой почтой и паролем на обоих устройствах. Чтобы перенести исходные заметки, открыть «История» → «Импортировать записи» и выбрать отдельный личный JSON-файл.

GitHub Pages не запускает серверную базу. На бесплатном плане GitHub Pages требует публичный репозиторий; перед публикацией кода нужно отдельно согласовать видимость. Для Pages установить `BASE_PATH=/имя-репозитория/`. Другой статический хостинг может подключаться к приватному GitHub-репозиторию; по умолчанию `BASE_PATH=/`.

## Проверка

`npm run build` проверяет TypeScript и собирает клиент. Для проверки изоляции данных на живой базе использовать два отдельных аккаунта: второй не должен видеть или менять записи первого. Параллельная запись со старой ревизией должна возвращать конфликт `40001`. Эти проверки требуют подключённого Supabase и не считаются выполненными одной локальной сборкой.
